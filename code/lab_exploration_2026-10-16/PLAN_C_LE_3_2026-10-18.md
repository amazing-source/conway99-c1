# Plan chiffré pour les droites à c ≤ 3 (LAB, 18/10/2026)

Demande de l'utilisateur (18/10, vers 01 h) : un plan court et chiffré, AVANT de lancer quoi que ce soit. Le seul calcul
fait pour ce plan est le comptage `cmin3_count.py` : 4 min, un processus, priorité minimale, sortie dans
`cmin3_count.log`.

## Diagnostic

- c_min = 4 (Codex) se réduit à une liste finie, parce que le voisinage d'une droite se casse en petits morceaux de
  6, 12 ou 18 sommets.
  - Le rang du Gram des rectangles est borné par dim ker C = |E(J)| − |V(J)| + nombre de composantes bipartites
    (Codex, `QUOTIENT_COMPOSANTES_RACINE` (2)), soit ≤ 4.
  - Codex écrit lui-même : « La branche minimum global c<=3 reste également ouverte et hors de cette couverture. »
- À c = 1 partout, dim ker C = 14 (incidence de K7) : la méthode ne donne plus de petits domaines.
- Empiler des filtres exacts tue nos données, mais ces données sont biaisées et ne forment pas une couverture. Ce qui
  manque : une réduction finie, ou un argument global.

## Fait combinatoire utile (élémentaire)

S'il y a au plus 32 droites à c ≤ 2, l'une des 99 racines n'est sur aucune d'elles (3 × 32 = 96 < 99) : ses 7 droites
ont alors toutes c ≥ 3. D'où la dichotomie :
- (I) une racine dont les 7 droites ont c ≥ 3 : c'est la route B ;
- (II) chaque sommet est sur une droite à c ≤ 2, donc au moins 33 droites ont c ≤ 2 : c'est la route C.
